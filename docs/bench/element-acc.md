# 元素正确识别率基准 (三方): 复杂页面上的"点的是不是那个元素"

> 动机: 此前七套基准全部验证"结果状态对", 从未系统测"动作落在语义正确的元素上"。
> 同时回答一个产品质疑: **省 token 省的是不是该省的?** —— 把两者放同一复杂页面上对照。
> 复现: `.venv/Scripts/python.exe -u bench/element_acc.py` · 原始数据 `element-acc.json`
> 夹具: `bench/fixture_acc/` (运营后台 / 商品网格 / 入驻向导), 全部 data-acc 埋点 +
> capture 相位点击/输入记录器, 真值 = 实际接收事件的元素。

## 页面复杂度设计 (专打快照裁剪策略的盲区)

- **同名按钮海**: 4 卡片 × 编辑/刷新, 20 行订单 × 编辑/删除/复制 (第 7 行删除禁用, 15+ 行操作列隐藏)
- **相似名**: 提交订单 / 提交申请 / 重新提交订单; 姓名 / 联系人姓名 / 紧急联系人姓名
- **隐藏陷阱**: display:none 的"删除全部"(快照不应暴露); disabled 按钮 (点击应报错非静默)
- **icon-only**: 仅 aria-label 的顶栏图标钮
- **shadow DOM** 组件按钮、**iframe** 表单 (输入+按钮)
- **模态遮罩**: 两步流程, 打开后再点弹窗内按钮
- **整表重渲染**: 价格排序后 24 个"加入购物车"全部换 ref (ref 代际链考验)
- **值选择**: 按"商品编号 G02"/"体脂秤"定位按钮 —— **要求快照携带商品文本**

## 方法

resolver 只用各家快照输出里存在的信息定位元素 (nexus: 平铺行+box 文档序扫描;
pw: YAML 缩进子树; cdt: 平铺行邻近窗口), 执行后读 `window.__hits` 判定实际命中。
目标不在视图时允许滚动翻页 (最多 3 屏, 三方同规则)。误点 decoy 单独计分。

## 结果 (26 案例)

| | nexus | playwright-mcp | chrome-devtools-mcp |
|---|---|---|---|
| 元素命中率 | 92% (46/50) | 92% (46/50) | **100% (48/48)** |
| 总 token | 74,237 | 73,471 | **46,603** |
| 误点 decoy | 0 | 0 | 0 |

三家全过: 同名卡片/表格行消歧、相似名、icon-only、隐藏/禁用陷阱、shadow DOM、
iframe、模态流程、重渲染后重定位 (ref 代际链)。

## 关键发现: 我们的质疑被数据证实

**grid-by-name / grid-by-price-88 是仅有的失败案例, 且 nexus 与 pw 双双失败, cdt 满分。**

这两个案例要求从"商品编号 G02"/"体脂秤"等**商品文本**定位到对应按钮。cdt 的
StaticText 逐节点平铺 dump 把商品名/价格/编号全带上了, 邻近窗口一查一个准;
而 nexus 默认快照只含可交互元素 (24 个一模一样的"加入购物车"), 商品文本被
阅读模式裁掉 —— **信息不在快照里, 再聪明的 agent 也无法消歧**。pw 的 YAML 同样不含这些文本。

**结论: 我们此前省下的 token 里, 有一部分确实是在砍定位所需的信息。**
"省 token"不能只看总量, 要看"单位准确率成本"。本套件就是这只金丝雀。

### 修复方向 (未实施, 待决策)

interactive 快照对**同名冲突的候选组**附带邻近文本摘要 (如按钮前一行 span 文本),
只在冲突时付出额外 token: 无冲突页面成本不变, 冲突页面用 ~200 tok 换回识别率。
